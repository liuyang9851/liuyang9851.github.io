## Shell 元字符

### 1. 命令执行与分隔

- `;`：顺序执行多条命令
- `|`：管道，前 stdout → 后 stdin
- `&`：后台执行命令
- `&&`：逻辑与，前成功则执行后
- `||`：逻辑或，前失败则执行后
- `()`：子 Shell 中执行
- `{}`：代码块/复合命令
- `$()`：命令替换（推荐）
- `` ` ``：反引号，旧式命令替换

### 2. 文件名通配符（globbing）

- `*`：匹配任意字符（含空）
- `?`：匹配任意单个字符
- `[...]`：匹配括号内任一字符
- `[^...]` / `[!...]`：匹配不在括号内的字符
- `{...}`：序列扩展，如 `{1..10}`、`{a,b,c}`

### 3. 输入/输出重定向

- `<`：标准输入重定向
- `>`：标准输出覆盖
- `>>`：标准输出追加
- `2>`：标准错误覆盖
- `2>>`：标准错误追加
- `&>`：同时重定向覆盖 stdout + stderr

```bash
# 假设 ls 一个存在的文件和一个不存在的文件
ls exist.txt not_exist.txt &> result.txt
# result.txt 中同时包含正常输出和错误信息
```

- `&>>`：同时追加 stdout + stderr
- `2>&1`：让stderr指向stdout指向的位置

```bash
  # 正确写法：先让 stdout 指向文件，再将 stderr 指向同样的位置
  cmd > output.txt 2>&1

  # 错误写法：先 2>&1（此时 stdout 还是终端），再 > file，导致 stderr 仍然去终端
  cmd 2>&1 > output.txt   # 错误信息不会进入文件
```

- `1>&2`：stdout 合并到 stderr
- `<<EOF`：Here Document 多行输入。创建一个**多行字符串**作为命令的标准输入，直到遇到 **分隔符** （此处为 `EOF`，可自定义）为止。结束符必须**单独一行**且**顶格写**。
- `<<<`：Here String 单行字符串输入。会在字符串末尾自动加一个换行符。相当于 `echo "string" | 命令` 但更高效（无需起子进程管道）。
- `<>`：读写方式打开文件

### 4. 变量与扩展

- `$`：变量/参数引用（变量名可以以字母、数字、下划线组成，但不能以数字开头。）
- `${var}`：变量扩展（精确边界）

```bash
  var="foo"
  echo "$var_bar"    # 错误：Shell 会去找变量 var_bar，可能不存在
  echo "${var}_bar"  # 正确：输出 foo_bar
```

- `$(( 表达式 ))`：整数算术运算。只支持整数，不支持浮点数（浮点需用 bc 或 awk）。内部变量名前不需要 $ ，但也可以加。可以赋值：`$(( a += 5 ))` 会改变变量 `a` 的值。 `$[ ]` 形式（已过时，不推荐）
- `$*`：所有参数合并成一个字符串，以 IFS 分隔
- `"$*"`：所有参数合并成一个字符串，以 IFS 的第一个字符连接（通常为空格）
- `$@`：每个参数独立展开，可能会进一步进行单词拆分（如果包含空格）
- `"$@"`：每个参数作为独立的带引号的字符串 —— 这是最推荐的形式，能保留参数中的空格和特殊字符
- `$?`：上一条命令退出码
- `$$`：当前 Shell 进程 PID

```bash
#!/bin/bash
# 假设脚本被调用为：./test.sh "hello world" "foo bar"
for arg in $*; do
    echo "[$arg]"
done
# 输出： [hello] [world] [foo] [bar]   (单词被拆分)
for arg in "$*"; do
    echo "[$arg]"
done
# 输出： [hello world foo bar]   (一个字符串)
for arg in $@; do
    echo "[$arg]"
done
# 输出： [hello] [world] [foo] [bar]  (同样被拆分)
for arg in "$@"; do
    echo "[$arg]"
done
# 输出： [hello world] [foo bar]   (保留了原始参数边界)
```

### 5. 引号与转义

- `' '`：强引用，不解析任何特殊字符
- `" "`：弱引用，可解析变量、命令替换
- `\`：转义字符，使元字符变回普通字符

### 6. 注释与历史

- `#`：注释
- `!`：历史命令调用（bash 特有）

### 7. 路径与特殊位置

- `~`：家目录
- `/`：路径分隔符
- `.`：当前目录
- `..`：上级目录
- `-`：上次cd到的目录

### 8. 测试与条件

- `[[ 条件 ]]`：增强版条件测试（bash 特有）
- `=` / `==` / `!=` / `<` / `>`：字符串比较（在 [[ ]] 中，= 和 == 等价，都表示字符串相等。）
- `-eq` / `-ne` / `-lt` / `-le` / `-gt` / `-ge` 等：数值比较

## Bash 的处理过程

### 1. 处理引号和转义字符

1. `\`（反斜杠）：去掉反斜杠，把其后面的字符当成普通字符（仅处理转义功能，不涉及其他解析）
2. `'`（单引号）：暂时不去掉单引号，把单引号里的内容全部当成普通字符，禁止所有替换（变量、命令、转义均无效）
3. `"`（双引号）：暂时不去掉双引号，把双引号里的内容当成普通字符，但仍允许 `$`、`` ` ``（`$()`）、`\` （只对 $、`、"、\ 和换行有效，对其他字符如 ! 不一定转义）符号生效

### 2. 用分隔符分词

仅使用 `IFS` 默认分隔符（空格、Tab、换行）来分词，将命令行拆分为多个独立的“词”（参数/命令）。

- 注意：`; | & > < && ||` 是 Shell 元字符/命令运算符，**不是分词符**，不参与分词过程。

### 3. 做特殊符号扩展（按以下顺序执行）

1. `{ }`（花括号）：花括号扩展，用于生成连续/批量字符串（如 `{1..5}` 生成 1 2 3 4 5）
2. `~`（波浪号）：波浪号扩展，默认替换为当前用户家目录（如 `~` 等价于 `/home/用户名`）
3. `$`（参数/变量替换）：替换变量/参数的值；若没用花括号 `{}`，会以空白、特殊符号（非变量名字符）作为变量边界；**仅无引号的变量替换后会尝试分词，双引号内的变量替换禁止分词**
4. `` ` ` ``、`$()`（命令替换）：执行括号/反引号内的命令，将执行结果替换到当前位置（`$()` 更推荐，支持嵌套）
5. `$(())`（算术扩展）：执行括号内的整数算术运算，将运算结果替换到当前位置
6. `* ? [...]`（路径名扩展）：匹配当前目录下符合规则的文件名（仅无引号时生效，引号内会当作普通字符）

### 4. IO 重定向、管道、后台

涉及 `> >> < 2> &> 2>&1 | & ;; && ||`，进程替换 `<() / >()`。

- 作用：定义命令的输入/输出方向、命令间的管道关联、命令执行方式（前台/后台）、命令间的逻辑关系（与/或）

### 5. 别名替换与命令类型判断

1. 别名替换：在命令解析完成后，若命令的第一个单词是已定义的别名，则替换为实际命令，然后重新解析（发生在大部分扩展之前）
2. 判断命令类型：在所有解析、扩展、引号剥离完成后，判断当前命令是 Shell 内置命令（如 `echo`、`cd`）还是外部命令（如 `ls`），为最终执行做准备

### 6. 删除引号

所有解析、扩展、重定向等操作全部完成后，删除所有作为语法符号的单/双引号（不删除转义后的引号 `\"` / `\'`），仅将引号内的纯文本传递给命令执行。

## 文件类型

可以通过 `ls -l` 输出的第一个字符来识别：

| 文件类型         | 标识符 | 说明                                         |
|------------------|--------|----------------------------------------------|
| **普通文件**     | `-`    | 包括文本文件、二进制程序、脚本、压缩包等。   |
| **目录**         | `d`    | 文件夹，用于组织其他文件。                   |
| **符号链接**     | `l`    | 指向另一个文件或目录的快捷方式。             |
| **字符设备**     | `c`    | 以字节流方式顺序访问的设备（如键盘、串口）。 |
| **块设备**       | `b`    | 以数据块方式随机访问的设备（如硬盘、U盘）。  |
| **管道（FIFO）** | `p`    | 用于进程间通信的命名管道。                   |
| **套接字**       | `s`    | 用于网络或本地进程间通信的 socket 文件。     |

### 补充说明

- **普通文件**的判定可通过 `file` 命令进一步查看具体类型（如 ASCII text、ELF executable 等）。
- **符号链接**指向的目标可能不存在（悬空链接）。
- 字符设备和块设备文件通常位于 `/dev/` 目录下，由系统动态创建。
- 管道和套接字多用于程序间的通信，一般用户很少直接操作。

## 文件目录

Linux 系统的目录结构遵循 **FHS**（Filesystem Hierarchy Standard，文件系统层次结构标准），所有目录都挂载在根目录 `/` 下。以下是常见目录及其功能：

| 目录     | 功能说明                                                                                                                                                                                                                                                                                                |
|----------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `/`      | 根目录，整个文件系统的起点。                                                                                                                                                                                                                                                                            |
| `/bin`   | 存放**基本用户命令**（如 `ls`、`cp`、`cat`），**所有用户**都可执行。在部分发行版中，`/bin` 是 `/usr/bin` 的符号链接。                                                                                                                                                                                   |
| `/sbin`  | 存放**系统管理命令**（如 `fdisk`、`mkfs`、`ifconfig`），通常仅 `root` 用户可用。                                                                                                                                                                                                                        |
| `/etc`   | 存放**系统配置文件**（如 `/etc/passwd`、`/etc/fstab`、`/etc/ssh/sshd_config`）。                                                                                                                                                                                                                        |
| `/home`  | 普通用户的**家目录**，每个用户在 `/home/用户名` 下有私人目录。                                                                                                                                                                                                                                          |
| `/root`  | **root 用户的家目录**，普通用户无权访问。                                                                                                                                                                                                                                                               |
| `/boot`  | 存放**启动引导文件**（如内核 `vmlinuz`、初始内存盘 `initrd`/`initramfs`、GRUB 配置）。                                                                                                                                                                                                                  |
| `/dev`   | 存放**设备文件**（如 `/dev/sda` 硬盘、`/dev/tty` 终端、`/dev/null`）。                                                                                                                                                                                                                                  |
| `/proc`  | **虚拟文件系统**，提供进程和内核信息（如 `/proc/cpuinfo`、`/proc/meminfo`），数据存在于内存中。                                                                                                                                                                                                         |
| `/sys`   | **虚拟文件系统**，导出内核对象（设备、驱动、电源管理等），用于 sysfs。                                                                                                                                                                                                                                  |
| `/tmp`   | **临时文件**目录，所有用户可读写，系统重启后文件通常被清空（取决于配置）。                                                                                                                                                                                                                              |
| `/var`   | 存放**可变数据**：日志（`/var/log`）、邮件（`/var/mail`）、缓存（`/var/cache`）、运行时文件（`/var/run`）等。                                                                                                                                                                                           |
| `/usr`   | **系统主要资源目录**，存放只读的用户程序和数据。子目录包括：<br> - `/usr/bin`：大部分用户命令<br> - `/usr/sbin`：大部分系统管理命令<br> - `/usr/lib`：库文件<br> - `/usr/include`：头文件<br> - `/usr/share`：架构无关的数据（文档、图标等）<br> - `/usr/local`：本地安装的软件（通常源码编译安装至此） |
| `/opt`   | 可选的**第三方软件包**安装目录（如 `/opt/google/chrome`）。                                                                                                                                                                                                                                             |
| `/srv`   | 服务（service）数据目录，存放 Web、FTP 等服务的数据文件。                                                                                                                                                                                                                                               |
| `/mnt`   | 临时挂载点（手动挂载文件系统）。                                                                                                                                                                                                                                                                        |
| `/media` | 自动挂载的可移动媒体（如 USB 盘、光盘）。                                                                                                                                                                                                                                                               |
| `/run`   | 存放**运行时变量数据**（自系统启动以来的进程信息），如 PID 文件、socket 等。与 `/var/run` 常互为链接。                                                                                                                                                                                                  |

## 磁盘文件命名

在 Linux 系统中，磁盘设备的文件名遵循一定的命名规则，常见的如 `sda`、`sdb`、`sdb3` 等。下面详细解释其含义。

### 一、传统命名规则（基于设备类型）

| 前缀     | 含义                                          | 示例                 |
|----------|-----------------------------------------------|----------------------|
| **sd**   | **S**CSI 磁盘（广义，包括 SATA、SAS、USB 等） | `sda`、`sdb`、`sdc`  |
| **hd**   | IDE 磁盘（较老的 PATA 接口）                  | `hda`、`hdb`         |
| **vd**   | VirtIO 磁盘（虚拟化环境，如 KVM）             | `vda`、`vdb`         |
| **nvme** | NVMe 固态硬盘（非易失性内存快速通道）         | `nvme0n1`、`nvme1n2` |

### 二、名称结构解析（以 `sda`、`sdb`、`sdb3` 为例）

#### 1. `sd` 表示设备类型

- **s**：代表 SCSI 磁盘。
- **d**：代表 disk（磁盘）。

#### 2. 第 3 个字母（a, b, c...）表示磁盘序号

- `a` → 第一块 SCSI 磁盘
- `b` → 第二块 SCSI 磁盘
- `c` → 第三块，依此类推。

#### 3. 数字表示分区号

- 不带数字：表示**整个磁盘设备**（如 `/dev/sda`）。
- 数字 1、2、3...：表示磁盘上的**分区**（如 `/dev/sda1` 是第一分区，`/dev/sda2` 是第二分区）。
- 例如 `sdb3`：第二块 SCSI 磁盘的**第三个分区**。

### 三、特殊命名规则

#### NVMe 固态硬盘

命名格式：`nvme0n1`、`nvme0n1p2`

- `nvme`：设备类型。
- `0`：控制器编号（第一个控制器）。
- `n1`：命名空间（namespace）编号，通常为 1。
- `p2`：分区号（p 表示 partition），例如 `nvme0n1p1` 是第一个分区。

### 四、示例对照表

| 设备文件         | 含义                                             |
|------------------|--------------------------------------------------|
| `/dev/sda`       | 第一块 SCSI 磁盘（整个硬盘）                     |
| `/dev/sda1`      | 第一块 SCSI 磁盘的第一个分区                     |
| `/dev/sda2`      | 第一块 SCSI 磁盘的第二个分区                     |
| `/dev/sdb`       | 第二块 SCSI 磁盘                                 |
| `/dev/sdb3`      | 第二块 SCSI 磁盘的第三个分区                     |
| `/dev/hda`       | 第一块 IDE 磁盘                                  |
| `/dev/nvme0n1`   | 第一个 NVMe 控制器下的第一个命名空间（整个设备） |
| `/dev/nvme0n1p2` | 该 NVMe 设备的第二个分区                         |

### 五、查看磁盘信息命令

- `lsblk`：以树形结构显示所有块设备及分区。
- `fdisk -l`：列出磁盘和分区详情（需 root）。
- `blkid`：显示设备的 UUID、LABEL 等信息。

### 六、总结

- `sd` 开头表示 SCSI/SATA/USB 磁盘；`a`、`b` 是磁盘顺序；数字是分区号。
- 不同接口类型有不同的前缀（`hd` 为 IDE，`vd` 为虚拟化，`nvme` 为 NVMe）。
- 分区编号从 1 开始，1-4 为主分区或扩展分区，5 以上为逻辑分区。

编辑 `/etc/fstab` 以及进行磁盘分区管理。

## 文件的三个时间

- mtime：最后修改时间（modify）
- ctime：状态改变时间（change）
- atime：最后访问时间（access）

### 一、三个时间戳详解

| 时间戳    | 全称              | 含义                           | 更新触发条件                                                                      | 查看命令               |
|-----------|-------------------|--------------------------------|-----------------------------------------------------------------------------------|------------------------|
| **mtime** | Modification Time | 文件**内容**最后被修改的时间   | 写入、追加、截断文件等改变数据内容的操作                                          | `ls -l` (默认)，`stat` |
| **ctime** | Change Time       | 文件**元数据**最后被改变的时间 | 更改权限(`chmod`)、所有者(`chown`)、文件名(`mv`)、链接数，或 mtime/atime 被更新时 | `ls -lc`，`stat`       |
| **atime** | Access Time       | 文件**内容**最后被读取的时间   | 读取文件内容（如 `cat`、`less`、`head`）                                          | `ls -lu`，`stat`       |

### 二、操作对时间戳的影响

| 操作示例                         | mtime | ctime | atime               |
|----------------------------------|-------|-------|---------------------|
| `echo "data" >> file` (修改内容) | 更新  | 更新  | 不变                |
| `cat file` (读取内容)            | 不变  | 不变  | 更新 (依赖挂载选项) |
| `chmod 644 file` (改权限)        | 不变  | 更新  | 不变                |
| `mv file newfile` (重命名)       | 不变  | 更新  | 不变                |
| `touch file` (更新时间戳)        | 更新  | 更新  | 更新                |
| `ls -l file` (只读元数据)        | 不变  | 不变  | 不变                |

> **注意**：`ctime` 无法手动设置，它总是记录最后一次 inode 变更的时间（包括 mtime/atime 的自动更新）。

### 四、特殊挂载选项对 atime 的影响

为了性能，现代 Linux 默认使用 **`relatime`**（相对 atime）挂载选项，atime 仅在以下情况更新：

- atime 早于 mtime 或 ctime
- atime 距离上次更新超过一定时间（通常是一天）

完全禁用 atime 更新可使用 **`noatime`**，这能减少磁盘写入，提高性能（尤其是频繁读取的服务器）。查看挂载选项：`mount | grep "^/dev"`。

### 六、目录的时间戳

目录本身也是一个文件，其三个时间戳含义略有不同：

- **mtime**：目录内容（文件列表）最后被修改的时间（如创建、删除、重命名文件）。
- **ctime**：目录元数据（权限、所有者等）或 mtime 改变时更新。
- **atime**：目录被读取时更新（如 `ls` 列出目录内容，但不会递归影响内部文件的 atime）。

### 注意

- `ls -l` 默认显示 mtime。
- 无法单独修改 ctime；任何尝试修改其他时间戳的操作都会导致 ctime 变为当前时间。
- 使用 `touch -a` 可只改 atime，`touch -m` 只改 mtime，但 ctime 总会随之更新。

## 通配符与正则表达式

## 文件

- 数据块（data blocks）：实际存储文件内容的地方。
- 索引节点（inode）：存储文件的元数据（权限、所有者、大小、时间戳、指向数据块的指针等）。每个文件（或目录）都有一个唯一的 inode 号。

## 硬链接（Hard Link）

- 多个文件名指向同一个 inode。
- 这些文件名可以分布在同一个文件系统（同一个分区）的不同目录中。
- 删除其中一个文件名，其他文件名依然可以访问文件数据（只是该 inode 的链接计数减 1）。
- 只有当链接计数变为 0 时，文件数据才会真正从磁盘上删除。

## 软链接（Symbolic Link / Symlink）

- 一个特殊的文件，其内容是指向另一个文件或目录的路径字符串（类似 Windows 的快捷方式）。
- 软链接有自己的 inode 和数据块（存储目标路径）。
- 可以跨文件系统、可以链接到目录、可以链接到不存在的目标（“悬空链接”）。
- 删除原始文件后，软链接变为“断裂链接”（broken link），访问会报错。

| 特性                   | 硬链接                                                    | 软链接                                                       |
|------------------------|-----------------------------------------------------------|--------------------------------------------------------------|
| **本质**               | 同一个 inode 的多个名字                                   | 独立文件，存储路径字符串                                     |
| **inode**              | 与源文件相同                                              | 不同（有自己的 inode）                                       |
| **跨文件系统**         | 不可以（inode 在本文件系统内唯一）                        | 可以                                                         |
| **链接目录**           | 不可以（避免循环，除 `.` 和 `..` 外）                     | 可以                                                         |
| **链接到不存在的目标** | 无法创建（目标必须存在）                                  | 可以创建（悬空链接）                                         |
| **对源文件删除的影响** | 数据不丢失（链接计数减 1）                                | 链接断裂（无法访问）                                         |
| **大小**               | 没有额外数据（仅是 inode 引用）                           | 存储路径字符串，通常很小                                     |
| **权限**               | 权限由 inode 统一管理，修改一个链接的权限会影响所有硬链接 | 软链接自身权限（通常 777）不重要，访问时取决于目标文件的权限 |
| **查找原始文件**       | 没有直接方法（所有硬链接平等）                            | 可用 `readlink` 读取目标路径                                 |
| **目录中的表现**       | 普通文件条目                                              | 特殊文件类型 `l`（符号链接）                                 |

### 用户与用户组核心概念

- 用户：Linux 系统登录身份，分为三类
  - 超级用户：`root`，UID=0，系统最高权限
  - 系统用户：UID 1-999，运行系统服务，禁止登录
  - 普通用户：UID≥1000，手动创建的登录用户
- 用户组：用户集合，用于统一授权
  - 主组：用户必须归属的唯一组，新建用户默认创建同名主组
  - 附加组：用户可归属的多个组，用于扩展权限

### UID 与 GID 规则

- UID：用户唯一身份标识
- GID：用户组唯一身份标识
- 系统约定：`root=0`，系统用户=1~999，普通用户=1000+

## 管理账户和组的6个命令

### useradd

- `-c`：添加用户注释/备注
- `-d`：指定自定义家目录
- `-e`：设置账户过期日期（YYYY-MM-DD）
- `-g`：指定用户**主组**
- `-G`：指定用户**附加组**（多组用逗号分隔）
- `-s`：指定登录 Shell（`/sbin/nologin` 禁止登录）


### usermod

- 用法与 `useradd` 一致，用于修改已有用户
- `-l`：修改用户名
- `-L`：锁定用户
- `-U`：解锁用户
- `-md`：修改家目录并迁移数据

```bash
usermod -l newtest test
usermod -G root test
```

### userdel

- `-r`：**彻底删除**（用户+家目录+缓存，常用）
- 无 `-r`：仅删除用户信息，保留家目录

```bash
userdel -r test
```

### groupadd

- `-g`：指定自定义 GID

```bash

```

### groupmod

- `-g`：修改 GID
- `-n`：修改组名

```bash
groupmod -n newgroup testgroup
```

### groupdel

- 仅可删除**空组**（无用户作为主组）
- 组为用户主组时，需先删除用户

### chmod

### 文字设定法

`chmod [ugoa][+-=][rwxugo] 文件/目录名`

| 选项 | 说明                |
|------|---------------------|
| r    | 读（read）          |
| w    | 写（write）         |
| x    | 执行（execute）     |
| u    | 属主（user）        |
| g    | 所属组用户（group） |
| o    | 其他用户（other）   |
| a    | 所有用户（all）     |
| +    | 增加权限            |
| -    | 删除权限            |
| =    | 修改权限            |

把符号后面的权限按符号规则修改到符号前面的权限上。

| 权限 | 对文件的影响                                                             | 对目录的影响                                                              |
|------|--------------------------------------------------------------------------|---------------------------------------------------------------------------|
| r    | 可以读取文件内容（如 cat、less）。                                       | 可以列出目录内容（如 ls），但需要 x 配合才能进入目录。                    |
| w    | 可以修改文件内容（如 vim、echo >>）。注意：删除文件需要父目录的 w 权限。 | 可以在目录中创建、删除、重命名文件或子目录。（前提是已有 x 权限进入目录） |
| x    | 可以执行文件（如二进制程序或脚本）。                                     | 可以进入目录（cd），也是访问目录内文件元数据的基础。                      |

| 特殊权限                                                             | 对**文件**的影响                                                                                                                                                         | 对**目录**的影响                                                                                                                                             |
|----------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **SUID** (Set User ID)<br>（出现在所有者执行位，如 `rwsr-xr-x`）     | 执行该文件时，进程的有效 UID 变为**文件所有者**的 UID（而不是执行者的 UID）。<br>**典型应用**：`/usr/bin/passwd`（普通用户执行时临时获得 root 权限修改 `/etc/shadow`）。 | **Linux 忽略**目录的 SUID 位（不产生效果，但可以设置）。                                                                                                     |
| **SGID** (Set Group ID)<br>（出现在组执行位，如 `rwxr-sr-x`）        | 执行该文件时，进程的有效 GID 变为**文件所属组**的 GID。<br>**典型应用**：某些游戏或特定工具需要组权限。                                                                  | 在该目录下**新建的文件或子目录**将**继承该目录的所属组**（而不是创建者的主组）。<br>常用于团队协作目录。                                                     |
| **Sticky-bit** (粘滞位) <br>（出现在其他用户执行位，如 `rwxrwxr-t`） | **历史意义**：曾用于请求内核将程序代码保留在交换区（现代 Linux 忽略）。<br>现在对文件**无实际作用**（除非特定系统配置）。                                                | 限制删除权限：**只有文件所有者、目录所有者或 root** 可以删除或重命名该目录下的文件，即使用户对该目录有 `w` 权限。<br> **典型应用**：`/tmp`（`drwxrwxrwt`）。 |

### 数字设定法

`chmod 属主权限数字属组用户权限数字其他用户权限数字 文件/目录名`

- `chmod` 数字表示：`r=4 w=2 x=1`，`chmod 755 file` → `rwxr-xr-x`
- 特殊权限：
  - SUID(`4`)：作用于可执行文件，执行时以文件所有者身份运行（`-rwsr-xr-x`）
  - SGID(`2`)：作用于目录时，目录内新建文件继承目录所属组
  - Sticky bit(`1`)：作用于目录（如 `/tmp`），只有文件所有者能删除自己的文件
- `umask`：设置新建文件/目录的默认权限（通常 `022`，对应目录 `755`，文件 `644`）
- `chattr +i file`：设置文件不可变（连 root 也无法修改/删除），`lsattr` 查看属性

## umask

一个八进制数。在创建文件时，从最大默认权限（文件为 666，目录为 777）中减去掩码值，得到最终权限。（一般是0022）

- `umask 新umask值`

## ACL权限（setfacl/getfacl）

### setfacl 设置ACL权限

`setfacl [-R] {-m|-x} <rules> 文件/目录名`

- `-R`：递归
- `-m`：修改/添加ACL权限
- `-x`：删除ACL权限

其中 `<rules>` 为可选的`d:`（只能对目录使用）加上

- `u:用户名或ID:权限`
- `g:组m名或ID:权限`
- `o:其他用户:[:]权限`
- `m:[:]权限`：对上述所有ACL权限做限制，掩码中没有的实际没有。
- 权限是三个字母那种

### getfacl 查看ACL权限

`getfacl 文件/目录名`

### 设置ACL权限的文件受命令的影响

| 操作                           | 效果                                  |
|--------------------------------|---------------------------------------|
| `ls -l` 显示 `+`               | 表示该文件/目录有扩展 ACL             |
| `chmod` 改变 `group` 权限      | 实际改变的是 mask（如果存在扩展 ACL） |
| `chmod` 改变 `user/other` 权限 | 直接修改对应的 ACL 条目               |
| `setfacl -b`                   | 删除所有扩展 ACL，恢复为传统权限      |

## 进程管理

### 进程的类型

| 类型           | 说明                         | 特点                                                       | 示例                                               |
|----------------|------------------------------|------------------------------------------------------------|----------------------------------------------------|
| **交互式进程** | 由终端启动，与用户直接交互   | 前台运行，用户可输入/输出，终端关闭时进程通常终止          | `bash`、`vim`、`top`                               |
| **批处理进程** | 不依赖终端，批量处理任务     | 无需用户交互，通常提交到任务队列，顺序执行                 | 后台编译任务、`cron` 定时任务、`at` 命令提交的作业 |
| **守护进程**   | 系统启动时自动运行，常驻后台 | 无控制终端，提供系统服务，父进程通常为 `systemd` 或 `init` | `sshd`、`crond`、`httpd`、`rsyslogd`               |

### ps/pstree/pgrep 进程查看

#### ps 查看进程

- `-a` 显示所有进程
- `-f` / `-H` 显示进程树，等价于 --forest
- `-e` 在命令后显示环境变量
- `-w` / `-w` 宽行输出。通常用于显示完整的命令行
- `-u` 显示用户名和启动时间等信息
- `-e` 显示所有进程，等价于 `--A`
- `-x` 显示没有控制终端的进程
- `-f` 完全显示。增加用户名、PPID、进程起始时间

| 输出项 | 说明                            | 输出项      | 说明                                      |
|--------|---------------------------------|-------------|-------------------------------------------|
| PID    | 进程号                          | TIME        | 进程自从启动以来占用 CPU 的总时间         |
| PPID   | 父进程的进程号                  | USER        | 用户名                                    |
| TTY    | 进程从哪个终端启动              | %CPU        | 占用 CPU 时间与总时间的百分比             |
| STAT   | 进程当前状态                    | %MEM        | 占用内存与系统内存总量的百分比            |
| START  | 进程开始执行的时间              | SIZE        | 进程代码大小+数据大小+栈空间大小，单位 KB |
| VSZ    | 进程占用的虚拟内存空间，单位 KB | COMMAND/CMD | 进程的命令名                              |
| RSS    | 进程所占用的内存空间，单位 KB   |             |                                           |

- `ps aux`：所有进程详细信息
- `ps -ef`：另一种格式的完整进程列表
- `pstree`：进程树（可选安装）
- `pgrep`：按名称查找进程 PID（如 `pgrep -u root nginx`）

### kill/pkill/killall 进程终止

- `kill PID`：向进程发送信号（默认 `TERM`）
- `kill -9 PID`：强制终止
- `kill -HUP PID`：重新加载配置文件（常用于守护进程）
- `pkill 进程名`：按名称终止
- `killall 进程名`：终止所有同名进程

### 前后台任务

| 命令或快捷键 | 功能说明                                                         |
|--------------|------------------------------------------------------------------|
| cmd &        | 命令后的&符号表示将该命令放到后台运行，以免霸占终端              |
| nohup cmd &  | 将该命令放到后台运行，以免霸占终端，且用户注销后命令依然继续执行 |
| `<Ctrl+D>`   | 终止一个正在前台运行的进程（含有正常含义）                       |
| `<Ctrl+C>`   | 终止一个正在前台运行的进程（含有强行含义）                       |

| jobs         | 显示后台作业和被挂起的进程                                       |

#### jobs 查看当前 Shell 的后台任务

- `-l`：显示进程 PID。
- `-p`：只显示 PID。
- `-r`：仅显示运行中的作业。
- `-s`：仅显示暂停的作业。

#### fg 在前台恢复运行一个被挂起的进程

`fg %n`

将后台作业（或暂停的作业）恢复到前台运行。%n 是作业号（如 %1、%2）。如果不指定作业号，默认将当前作业（带 + 标记的）调回前台。

#### bg 在前台恢复运行一个被挂起的进程

`bg %n`

将一个已挂起（暂停）的作业（例如按 Ctrl+Z 暂停的进程）在后台恢复运行。

### 进程优先级

- `nice -n 优先级 command`：以指定优先级启动（-20 最高，19 最低）
- `renice 优先级 -p PID`：修改已有进程优先级

### systemd 服务管理（systemctl）

- `systemctl status 服务名`：查看服务状态
- `systemctl start/stop/restart 服务名`：启动/停止/重启
- `systemctl enable --now 服务名`：设置开机自启并立即启动
- `systemctl disable 服务名`：取消开机自启
- `journalctl -u 服务名 -f`：查看服务日志（实时）

### 定时任务

- `crontab -e`：编辑当前用户的定时任务
  - 格式：`分 时 日 月 周 命令`（如 `0 2 * * * /backup.sh`）
- `crontab -l`：列出当前用户的定时任务
- `at`：一次性定时任务（如 `at now + 5 minutes`，然后输入命令，`Ctrl+D` 结束）

## 磁盘分区类型

MBR（Master Boot Record，主引导记录）

GPT（GUID Partition Table，全局唯一标识分区表）

| 分区类型 | 推荐命令行工具    | 图形工具  | 脚本工具           |
|----------|-------------------|-----------|--------------------|
| **MBR**  | `fdisk`, `parted` | `gparted` | `sfdisk`, `parted` |
| **GPT**  | `gdisk`, `parted` | `gparted` | `sgdisk`, `parted` |

| 特性             | MBR                                                          | GPT                                                        |
|------------------|--------------------------------------------------------------|------------------------------------------------------------|
| 全称             | Master Boot Record                                           | GUID Partition Table                                       |
| 最大支持磁盘容量 | ≤ 2 TiB                                                      | ≥ 18 EiB（实际受操作系统限制）                             |
| 最大分区数量     | 4 个主分区，或 3 个主分区 + 1 个扩展分区（内含多个逻辑分区） | 通常 128 个（Windows限制），理论无上限                     |
| 引导方式         | BIOS + MBR                                                   | UEFI + GPT（也支持 BIOS+GPT，但需特殊设置）                |
| 数据冗余         | 无备份，MBR 位于磁盘第 0 扇区                                | 分区表在磁盘头部和尾部均有备份，更可靠                     |
| 分区标识         | 使用分区类型 ID（如 0x83、0x82、0x07）                       | 使用分区类型 GUID（如 Linux 文件系统、swap、EFI 系统分区） |

## 磁盘设备的命名

### SATA / SCSI / SAS / USB 磁盘（主流）

命名格式：sdX（X 为 a, b, c, ...）

- sd：代表 SCSI disk（包括 SATA、SCSI、SAS、USB 等，因为这些接口都使用 SCSI 命令集）。
- 后续字母：a 表示第一块盘，b 第二块，依此类推（最多 26 个，sda ~ sdz，超过用 sdaa 等）。
- 分区编号：如 sda1（第一块盘的第一个分区）、sdb3（第二块盘的第三个分区）。

### IDE 磁盘（较老）

命名格式：hdX（X 为 a, b, c, ...）

- hd：代表 Hard disk（IDE 磁盘）。
- 字母：主控制器上的主盘为 hda，主控制器从盘为 hdb，第二控制器主盘为 hdc，依此类推。
- 分区编号：如 hda1、hdb2。

### 光盘驱动器（CD/DVD/BD）

命名格式：srX 或 scdX

- sr：代表 SCSI rOM（即使光驱接口是 IDE，也模拟为 SCSI 设备）。现代 Linux 中几乎统一使用 srX。
- scd：旧命名，现在较少见（部分系统保留）。
- 字母序号：sr0 为第一个光驱，sr1 第二个，依此类推。

### 软盘驱动器

命名格式：fdX

- fd：代表 Floppy disk。
- 字母：fd0 为第一个软驱（A:），fd1 第二个（B:）。

### NVMe固态硬盘

命名格式：nvmeXnY（或 nvmeXnYpZ）

- nvme0：第一个 NVMe 控制器。
- n1：该控制器下的第一个命名空间（namespace，通常每个 NVMe 设备有一个命名空间）。
- p1：分区 1（如果存在分区）。

| 接口类型                | 常见命名  | 示例                             | 备注                 |
|-------------------------|-----------|----------------------------------|----------------------|
| SATA / SCSI / SAS / USB | `sdX`     | `/dev/sda`, `/dev/sdb1`          | 现代通用命名         |
| IDE (PATA)              | `hdX`     | `/dev/hda`                       | 旧系统或旧驱动       |
| 光盘 (CD/DVD)           | `srX`     | `/dev/sr0`                       | 也可出现 `/dev/scd0` |
| 软盘                    | `fdX`     | `/dev/fd0`                       | 已淘汰               |
| NVMe SSD                | `nvmeXnY` | `/dev/nvme0n1`, `/dev/nvme0n1p2` | 高速存储             |
| SD/MMC 卡               | `mmcblkX` | `/dev/mmcblk0p1`                 | 嵌入式常用           |

注意：**命名顺序**（如 `sda` vs `sdb`）不保证固定，**不应依赖字母顺序进行永久配置**，应使用 UUID 或 LABEL 挂载。

## 文件系统

### 文件系统的类型

文件系统是操作系统用于**管理磁盘上的数据**的一种结构，它决定了文件如何存储、组织、命名、访问以及如何记录元数据（权限、时间戳等）。按照功能和应用场景，文件系统可以分为以下几种类型：

| 类型                    | 说明                                                         | 示例                                                                    |
|-------------------------|--------------------------------------------------------------|-------------------------------------------------------------------------|
| **磁盘文件系统**        | 直接管理硬盘、SSD、U盘等块设备上的数据                       | ext4, XFS, Btrfs, NTFS, FAT32, exFAT                                    |
| **网络文件系统**        | 通过网络访问远程主机上的文件系统                             | NFS, SMB/CIFS, AFS, GlusterFS                                           |
| **伪文件系统**          | 不占用实际磁盘空间，用于向用户空间导出内核数据结构或系统信息 | procfs (`/proc`), sysfs (`/sys`), tmpfs (`/dev/shm`), devtmpfs (`/dev`) |
| **集群/分布式文件系统** | 多台机器共享存储，提供统一命名空间                           | GFS2, Ceph, GlusterFS, Lustre                                           |
| **特殊用途文件系统**    | 用于特定场景，如加密、压缩、只读等                           | squashfs, cramfs, ecryptfs, fuse（用户空间文件系统框架）                |

### Linux 支持的文件系统类型

Linux 内核支持非常丰富的文件系统（通过内核模块或内建支持）。以下是常见且广泛使用的文件系统：

| 文件系统         | 特点                                                                        | 典型用途                                        |
|------------------|-----------------------------------------------------------------------------|-------------------------------------------------|
| **ext4**         | Linux 原生，兼容性好，支持大文件（16TB 单文件，1EB 卷），日志型，性能稳健   | 大多数 Linux 发行版的默认根文件系统             |
| **XFS**          | 高性能，支持超大文件系统（8EB），擅长处理大文件和高并发，也支持日志         | RHEL/CentOS 7+ 默认，适合大型存储服务器         |
| **Btrfs**        | 先进功能：快照、压缩、去重、子卷、在线扩容收缩，类似 ZFS                    | 追求高级存储功能的环境（openSUSE、Fedora 可选） |
| **ext3 / ext2**  | ext4 的前身，ext3 带日志，ext2 无日志（适合闪存设备）                       | 老旧系统或嵌入式                                |
| **FAT32 / VFAT** | 兼容性好，几乎所有操作系统支持，单文件 <4GB                                 | U 盘、跨平台交换数据                            |
| **exFAT**        | FAT32 的替代，支持大文件（>4GB），广泛用于 SDXC 卡和 U 盘                   | 大容量移动存储                                  |
| **NTFS**         | Windows 原生文件系统，Linux 通过 `ntfs-3g`（用户态驱动）读写                | 双系统访问 Windows 分区                         |
| **ISO 9660**     | 光盘文件系统（CD/DVD）                                                      | 挂载 ISO 镜像或光盘                             |
| **UDF**          | 通用磁盘格式，用于光盘和可重写光介质                                        | DVD/BD 视频光盘                                 |
| **tmpfs**        | 内存中的临时文件系统，重启数据丢失                                          | `/tmp`、`/run`、`/dev/shm`                      |
| **procfs**       | 伪文件系统，导出进程和内核信息                                              | `/proc`                                         |
| **sysfs**        | 伪文件系统，导出设备与驱动信息                                              | `/sys`                                          |
| **devtmpfs**     | 设备文件系统，自动管理 `/dev` 下的设备节点                                  | `/dev`                                          |
| **squashfs**     | 只读、压缩的文件系统，用于 Live CD、容器镜像                                | snap 包、嵌入式只读根文件系统                   |
| **FUSE**         | 用户态文件系统框架，允许非特权用户创建自己的文件系统（如 `sshfs`、`encfs`） | 挂载远程目录、加密目录                          |

### 查看当前系统支持的文件系统

```bash
# 查看已加载的文件系统模块
ls /lib/modules/$(uname -r)/kernel/fs/

# 查看内核支持的文件系统列表
cat /proc/filesystems
```

### 创建文件系统 mkfs

（make file system）

`mkfs -t 类型 设备` 或使用专用命令，如 `mkfs.ext4 /dev/sdb1`

- `-L` 卷标：设置卷标（如 -L data）
- `-N` inode数：指定 inode 数量（ext4）
- `-m` 百分比：保留块百分比（默认 5%）
- `-f`：强制创建（覆盖已有文件系统）
- `mkfs.ext4 /dev/sdb1` 在 /dev/sdb1 上创建 ext4 文件系统
- `mkfs.xfs /dev/sdc1` 创建 XFS 文件系统
- `mkfs.vfat /dev/sdd1` 创建 FAT32 文件系统

### 挂载文件系统 mount

挂载是将一个设备（或分区）关联到目录树中某个目录（挂载点）的过程。

`mount [选项] 设备 挂载点`

`mount /dev/sdb1 /mnt/data` 挂载 `/dev/sdb1` 到 `/mnt/data`

- `mount` 列出所有挂载点
- `findmnt` 树形显示（更清晰）
- `lsblk` 显示设备与挂载点
- `df -h` 查看磁盘使用及挂载点

### 永久挂载文件系统 编辑 /etc/fstab 文件

文件格式：`设备     挂载点     文件系统类型   挂载选项   dump   pass`

### 卸载文件系统 umount

卸载是指断开设备与挂载点的关联。卸载前要确保没有进程正在使用该挂载点。

`umount 挂载点` 或 `umount 设备`

- `-l`：懒惰卸载（lazy unmount），立刻断开，等不忙时真正清理
- `-f`：强制卸载（用于 NFS 等远程文件系统，本地强制通常无效）
- `lsof /mnt/data` 查看哪个进程在使用
- `fuser -v /mnt/data`显示使用该挂载点的进程

## 磁盘限额

磁盘配额（quota）是 Linux 用来限制用户、用户组或目录对磁盘资源使用的核心管理工具，能有效防止个别用户过度占用存储空间。它主要限制两个方面：一是文件占用的磁盘容量（blocks），二是可创建的文件及目录数量（inodes）。

配额的限制方式分为两种：

- 软限制：用户可以暂时超过的临时限额，超过后系统会发出警告。
- 硬限制：用户绝对不能超过的“天花板”，达到后任何写入操作都将失败。

| 命令/步骤                                                     | 说明                           | 范例                                                      |
|:--------------------------------------------------------------|:-------------------------------|:----------------------------------------------------------|
| `edquota -u <用户名>`                                         | 为用户设置容量或文件数限制     | `edquota -u alice`                                        |
| `setquota -u <用户名> <bsoft> <bhard> <isoft> <ihard> <设备>` | 通过命令行直接为用户设置限额   | `setquota -u bob 100M 120M 0 0 /dev/sda1`                 |
| `quota -u <用户名>`                                           | 查看指定用户的当前配额使用情况 | `quota -u alice`                                          |
| `repquota -a`                                                 | 生成所有分区的详细配额报告     | `sudo repquota -a`                                        |
| `quotaon <设备>`                                              | 在指定文件系统上激活配额功能   | `sudo quotaon /home`                                      |
| `quotaoff <设备>`                                             | 在指定文件系统上停用配额功能   | `sudo quotaoff /home`                                     |
| `xfs_quota -x -c 'limit ...' <挂载点>`                        | XFS文件系统专用配额管理        | `xfs_quota -x -c 'limit bsoft=500m bhard=600m bob' /home` |
| `xfs_quota -x -c 'report -h' <挂载点>`                        | XFS文件系统专用配额报告        | `xfs_quota -x -c 'report -h' /home`                       |

### ip 查看网络地址、路由信息、添加/删除ip地址

```bash
ip addr show                # 查看所有网卡的 IP 地址（简写：ip a）
```

- **`NetworkManager`**：这是 CentOS 7 中推荐的**动态网络控制**和**配置**服务，尤其适合有线和无线网络频繁切换的场景（如笔记本）。

| /etc/resolv.conf                       | 配置域名服务器客户端的配置文件，用于指定域名服务器的位置 |

### ping 测试主机之间的网络连通性

`ping [选项] 目标主机`，目标主机可以是 IP 地址或域名。

- `-c`：次数，发送指定数量的包后停止
- `-i`：秒数，设置发送包的时间间隔（默认 1 秒）
- `-s`：字节数，设置发送包的数据部分大小（默认 56，加上 ICMP 头共 64 字节）
- `-t`：TTL，设置 IP 包生存时间（仅限 IPv4）
- `-W`：秒数，设置等待响应的超时时间
- `-q`：安静模式，只显示统计摘要
- `-4` / `-6`：强制使用 IPv4 或 IPv6
- `-f`：洪水 ping（需 root），尽可能快速发送

### route 显示和操作 Linux 内核的 IP 路由表（主要是 IPv4）

## RPM （RPM Package Manager）

软件包管理系统。其中RPM的原名为（Red Hat Package Manager）

RPM具有如下5大功能：

- 安装：将软件从包中解出来，并且安装到硬盘。
- 卸载：将软件从硬盘清除。
- 升级：替换软件的旧版本。
- 查询：查询软件包的信息。
- 验证：检验系统中的软件与包中软件的区别。

### RPM包的命名格式

`name-version.type.rpm`

`名称-版本号-包的类型/架构.rpm`

其中包类型常见的为：

- `i[3456]86`：表示在 Intel x86 计算机平台上编译的。
- `x86_64`：表示在64位的Intel x86计算机平台上编译。
- `noarch`：表示已编译的代码与平台无关。
- `src`：表示软件源代码。
- `bind-9.2.1-16.i386.rpm` 是 bind（9.2.1-16）的 Intel 386 平台编译版本包。
- `bind-9.2.1-16.src.rpm` 是 bind（9.2.1-16）的源代码版本包。

### rpm 包管理

安装

`rpm -ivh package.rpm`

- `-i`：安装（install）
- `-v`：显示详细信息（verbose）
- `-h`：显示进度条（hash）
- `--nodeps`：忽略依赖关系检查（强制安装，可能导致软件不可用）
- `--force`：强制覆盖冲突文件（相当于 `--replacepkgs --replacefiles`）
- `--prefix /path`：指定安装前缀（部分包支持）

升级

`bash rpm -Uvh package.rpm`

- `-U`（upgrade）：如果已安装旧版本，则升级；否则安装新版本。
- `-F`（freshen）：仅当已安装更旧版本时才升级，不安装全新包。
- 常用选项与安装相同（`-v`、`-h`、`--nodeps` 等）。

卸载

`rpm -e package_name`

**注意**：卸载时使用**包名**（不是 rpm 文件名），可以通过 `rpm -qa` 查询已安装的包名。

- `--nodeps`：忽略依赖，强制卸载（可能导致依赖该包的其他软件出问题）
- `--test`：测试卸载，不实际执行

查询

```bash
rpm -q package_name                # 查询是否安装及版本
rpm -qa                            # 列出所有已安装的包
rpm -ql package_name               # 列出包安装的文件列表
rpm -qi package_name               # 显示包详细信息,显示名称、版本、架构、安装日期、描述等
rpm -qf /path/to/file              # 查询文件属于哪个包
rpm -qpi package.rpm               # 查看未安装 rpm 文件的信息
rpm -qpl package.rpm               # 查看未安装 rpm 将安装哪些文件
rpm -qf /etc/passwd                # 根据磁盘文件查询所属软件包
```

- 查询时**包名必须精确**（大小写敏感），若不确定完整包名，可先用 `rpm -qa | grep 关键词` 找到准确名称。
- `rpm -qf` 后跟的文件必须是由 RPM 包安装的（非手工创建的临时文件）。
- 以上命令通常无需 root 权限，但某些文件（如 `/proc` 下）可能查询失败。
- 若 RPM 数据库损坏，可执行 `rpm --rebuilddb` 修复。

## YUM

（Yellow dog Updater，Modified）

相比RPM的优点：

- 自动解决包的依赖性问题，能更方便地添加/删除/更新RPM包。
- 便于管理大量系统的更新问题。
- 可以同时配置多个仓库（repository）。
- 简洁地配置文件（/etc/yum.conf）。
- 保持与RPM数据库的一致性。
- 有比较详细的日志，可以查看何时升级安装了什么软件包等。

`yum  [全局参数] 命令 [命令参数]`

- `-y`：对yum命令的所有提问回答“是（yes）”。

使用 `yum`可以从软件仓库中自动解决依赖并安装、升级、卸载软件包。

安装

```bash
yum install <package_name>          # 安装单个包
yum install <pkg1> <pkg2>           # 安装多个包
yum install /path/to/local.rpm      # 从本地文件安装（自动解决依赖）
yum groupinstall "Group Name"       # 安装软件组（如 "Development Tools"）
```

- `-y`：自动确认，不询问
- `--nogpgcheck`：跳过 GPG 签名检查

升级

```bash
yum update <package_name>           # 升级指定包（不写包名则升级所有可升级的包）
yum upgrade                         # 与 update 类似，但连旧版本淘汰也处理（极少用）
yum check-update                    # 仅检查可升级的包，不执行升级
```

- `update` 和 `upgrade` 在大多数情况下等价。

卸载

```bash
yum remove <package_name>           # 卸载软件包（会一并卸载依赖它的包）
yum autoremove                      # 删除不再被需要的依赖包（类似 apt autoremove）
yum groupremove "Group Name"        # 移除软件组
```

## Shell变量分类

| 分类         | 说明                                                              | 示例                             |
|--------------|-------------------------------------------------------------------|----------------------------------|
| **局部变量** | 仅在当前 Shell 进程中有效，不会传递给子进程。                     | `name="Alice"`                   |
| **环境变量** | 会传递给由当前 Shell 启动的子进程（如脚本、命令）。通常大写命名。 | `export PATH="/usr/bin"`         |
| **特殊变量** | Shell 预定义的特殊变量（如 `$?`、`$0`、`$1` 等）。                | `echo $?` 显示上一条命令的退出码 |
| **位置参数** | 传递给脚本或函数的参数，`$1`、`$2`、`$*`、`$@`、`$#`。            | `./script.sh arg1 arg2`          |
| **数组变量** | 可以存储多个值的变量（Bash 支持一维数组）。                       | `arr=(a b c)`；`echo ${arr[1]}`  |

## Shell变量的作用范围

### 局部变量

- **作用域**：仅限于当前 Shell 进程（或当前函数内，如果使用 `local`）。
- 在子 Shell（如 `(command)`、`管道`、`脚本`）中不可见。

### 环境变量

- **导出**：使用 `export` 命令将局部变量提升为环境变量。
- **作用域**：当前 Shell 及其所有子进程（子 Shell、脚本、命令）都可以继承。

### 函数内变量

- 默认在函数内定义的变量是 **全局** 的（影响整个 Shell）。
- 若希望变量仅在函数内有效，需使用 `local` 关键字。

### 子 Shell 中的变量

子 Shell 是通过 `(command)`、命令替换 `` ` `` / `$()`、管道、后台任务 `&` 等方式启动的新的 Shell 进程。

- 子 Shell 会**继承**父 Shell 的**环境变量**（export 的变量），但不会继承局部变量。
- 子 Shell 内对环境变量的修改**不会影响**父 Shell（因为进程隔离）。

### 变量删除

使用 `unset` 删除变量（环境变量或局部变量）：

- 用户级：`~/.bash_profile`、`~/.bashrc`、`~/.profile`

|------------|-----------------------------------------|------------------------------------------------|---------------------------------------------------------------------|
| `BASH`     | 当前 Bash 解释器的完整路径              | `/bin/bash` 或 `/usr/bin/bash`                 | 判断是否运行在 Bash 环境下；配合 `$BASH_VERSION` 查看版本           |

## 扩展的变量替换

### 变量测试

| 表达式         | var 存在且非空时表达式的值 | var 存在且非空时 var 的值 | 其他情况（未定义/空值）时表达式的值 | 其他情况时 var 的值 |
|----------------|----------------------------|---------------------------|-------------------------------------|---------------------|
| `${var:-word}` | `$var`                     | 不变                      | `word`                              | 不变                |
| `${var:=word}` | `$var`                     | 不变                      | `word`                              | 被赋值为 `word`     |
| `${var:?word}` | `$var`                     | 不变                      | 输出信息 `word`，并终止脚本         | 不变                |
| `${var:+word}` | `word`                     | 不变                      | 空值                                | 不变                |

### 字符串计数、截取与大小写转换

| 表达式            | 功能说明                                                 |
|-------------------|----------------------------------------------------------|
| `${#var}`         | 返回字符串变量 `var` 的长度                              |
| `${var:m}`        | 返回从第 m 个字符（从 0 开始计数）到字符串末尾的子串     |
| `${var:m:len}`    | 返回 `${var}` 中从第 `m` 个字符开始，长度为 `len` 的部分 |
| `${var#pattern}`  | 删除 `${var}` 中开头部分与 `pattern` 匹配的最短部分      |
| `${var##pattern}` | 删除 `${var}` 中开头部分与 `pattern` 匹配的最长部分      |
| `${var%pattern}`  | 删除 `${var}` 中结尾部分与 `pattern` 匹配的最短部分      |
| `${var%%pattern}` | 删除 `${var}` 中结尾部分与 `pattern` 匹配的最长部分      |
| `${var/old/new}`  | 用 `new` 替换 `${var}` 中第一次出现的 `old`              |
| `${var//old/new}` | 用 `new` 替换 `${var}` 中所有的 `old`（全局替换）        |
| `${var/#old/new}` | 用 `new` 替换 `${var}` 中开头部分与 `old` 匹配的部分     |
| `${var/%old/new}` | 用 `new` 替换 `${var}` 中结尾部分与 `old` 匹配的部分     |
| `${var^^}`        | 所有字母转为大写                                         |
| `${var,,}`        | 所有字母转为小写                                         |
